# Animation benchmark

Run `pnpm bench:animation` from the repository root. Set `GIFENC_ANIMATION_ITERATIONS` to a positive integer to change the number of warm samples (default 3). The JSON report records Node and platform; compare runs on the same machine, runtime and settings. The five deterministic 160×90, 12-frame sequences cover gradients, moving shapes, a scene cut, subtitle-like edges and a moving translucent overlay composited onto an opaque background. The alpha case tests the resulting colors, not GIF transparency or disposal.

Each sequence reports the first run in this process as `cold_ms` and the median subsequent run for quantization, palette mapping and encoding. Later sequences can benefit from earlier process warmup, so these are not fresh-process cold starts. Stage times are summed over all frames; input generation and quality analysis are excluded. These are synchronous execution times, not UI responsiveness or yield time. RSS delta is a coarse process-level observation across all runs, affected by garbage collection and earlier cases; it is neither peak memory nor an allocation count.

The output is decoded to check frame count and duration. RGB RMSE compares decoded pixels with the source (lower is better); temporal error RMSE compares the change in reconstruction error between consecutive frames, including motion and scene cuts. Neither metric alone measures perceived quality or isolates flicker; inspect animations visually and use representative real footage before drawing conclusions. The synthetic sequences are reproducible baselines, not a substitute for the basketball video report or production workloads. The benchmark does not use chunking, sampling or reusable timing helpers; integrate those when their contracts land.
